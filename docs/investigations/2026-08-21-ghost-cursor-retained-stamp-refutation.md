# Фантомный курсор: bump quad_generation опровергнут как механизм; уточнённая цепочка через совпадение RetainedStamp

Дата: 2026-08-21
Задача: #658
Метод: read-only анализ кода на HEAD `7cd27f37e` (тот же коммит, из которого собран бинарник
с багом). Ни одного запуска, ни одной правки кода, ни один процесс не тронут.
Связь: follow-up к `2026-08-21-ghost-cursor-after-refocus-tab-switch.md` (далее «исходный отчёт»).
Настоящий отчёт проверил его гипотезу целиком: центральное звено опровергнуто, механизм пересобран.
Исходный файл оставлен без изменений; его раздел «Правдоподобный механизм» (звенья 2–4) и
«Кандидат на исправление» (пункт про сужение `quad_generation`) настоящим считаются опровергнутыми.

Актуальность цитат: `render/pane.rs`, `render/budget.rs`, `render/screen_line.rs`, `actions.rs`,
`resize.rs`, `config.rs` не входят в незакоммиченный diff — цитируются как в HEAD. Правки в

диапазоном 1678–1724.

## Резюме

1. Исходная цепочка «возврат фокуса → bump `quad_generation` → массовый cache-miss →
   `EmitRetained` устаревших строк со старым курсором» НЕРАБОТОСПОСОБНА. `quad_generation`
   входит в `RetainedStamp`, поэтому любой bump сбрасывает retained-строки панели целиком,
   после чего `RowSweep::decide` обязан строить каждую строку заново («never blank»).
   Первый кадр после bump — тяжёлый, но полностью свежий: устаревшие quad-ы эмитить неоткуда.
   Bump — не источник фантома, а его страховка.
2. Реальный механизм зеркальный: фантом возникает, когда штамп, наоборот, СОВПАДАЕТ.
   Переключение вкладок не бампает ничего; фоновая вкладка не рендерится, и её retained-строки
   замерзают вместе с последним нарисованным курсором. При возврате на вкладку все строки —
   cache-miss (контент ушёл вперёд), бюджет 40 мс перестраивает гарантированно только строку
   курсора и одну ротационную, остальные повторно эмитят старые quad-ы — включая курсорный блок
   в его прошлой позиции.

## 1. Опровержение исходного звена «bump → устаревшие строки»

- `RetainedStamp` (`crates/onlyterm-gui/src/termwindow/render/mod.rs:155-169`) содержит
  `quad_generation` (`render/mod.rs:158`) наряду с config/shape generation, пиксельными
  размерами и геометрией панели.
- Штамп строится и сравнивается один раз на панель за кадр в `paint_pane`
  (`crates/onlyterm-gui/src/termwindow/render/pane.rs:424-435` — построение,
  `pane.rs:439-471` — сравнение). При несовпадении запись панели заменяется на свежую с
  `rows: vec![None; dims.viewport_rows]` и `resume_row: 0` (`pane.rs:446-455`).
- После сброса `has_retained == false` для каждой строки, а `RowSweep::decide` при
  `!has_retained` безусловно возвращает `Build` независимо от бюджета
  (`crates/onlyterm-gui/src/termwindow/render/budget.rs:102`, «Never drawn before -> MUST NOT
  be blank»). Бюджет физически не может отложить строку, у которой нет retained-quad-ов.
- Следствие: звенья 2→4 исходной цепочки не смыкаются — массовый cache-miss, порождённый
  bump'ом, всегда сопровождается сбросом retained и потому заканчивается полным корректным
  rebuild'ом, а не пере-эмитом устаревших строк.

Места bump'а `quad_generation` (полный grep по crates/, их ровно три):
`window_handler.rs:32` (`focus_changed`, в обе стороны), `resize.rs:51` и `resize.rs:153`
(`apply_dimensions`). **Переключение вкладок среди них нет.**

## 2. Механизм фантома, подтверждённый чтением кода

Все пункты — OBSERVED (код на `7cd27f37e`), кроме явно отмеченного INFERRED.

1. Курсор запечён в quad-ы строки. Отдельного cursor-overlay нет (`paint_cursor` в коде
   отсутствует): `render_screen_line` вычисляет `cursor_cell`/`cursor_range` по условию
   `stable_line_idx == cursor.y` (`crates/onlyterm-gui/src/termwindow/render/screen_line.rs:108-123`)
   и рисует `cursor_sprite` в слоях строки (`screen_line.rs:317-430`). В кэш-ключ курсор входит
   как `Option<CursorProperties>` (`render/mod.rs:90-92`, `pane.rs:517-531`) — quad-ы строки
   «с курсором» и «без курсора» это разные записи `line_quad_cache`.
2. Фоновая вкладка не рендерится: `get_panes_to_render` возвращает панели только активной
   вкладки (`crates/onlyterm-gui/src/termwindow/actions.rs:2180-2188`); вывод панели невидимой
   вкладки не инвалидирует окно — гейт `is_pane_visible` в `mux_pane_output_event`
   (`crates/onlyterm-gui/src/termwindow/render_pipeline.rs:1678-1696, 1720-1724`). При этом PTY
   фоновой вкладки продолжает работать: контент и позиция курсора меняются без единого рендера.
3. Заморозка retained: пока вкладка неактивна, её запись в `retained_rows`
   (`crates/onlyterm-gui/src/termwindow/mod.rs:387`, `HashMap<PaneId, RetainedPaneRows>`)
   не обновляется. При возврате штамп СОВПАДАЕТ: `quad_generation` не менялся (см. §1 —
   переключение вкладок его не бампает), пиксельные размеры, геометрия и число строк те же
   (`pane.rs:424-435`) → сброса нет, `rows` и `resume_row` переживают простой
   (`pane.rs:443-444`).
4. Кадр возврата: у всех строк новый `shape_hash` (контент ушёл) → массовый cache-miss.
   `RowSweep::decide` (`budget.rs:88-121`):
   - строка курсора — всегда `Build` (`budget.rs:103`): теперь это нижняя строка у промпта,
     рисуется свежей. Отсюда корректный промпт внизу на скриншоте пользователя;
   - одна ротационная строка (`slot >= work_start`, `budget.rs:101,104`) — `Build`;
   - остальные при `has_retained == true` и просроченном дедлайне (40 мс —
     `default_tab_frame_build_budget_ms`, `crates/config/src/config.rs:1305-1307`) —
     `EmitRetained` (`budget.rs:106-119`): `pane.rs:763-782` пере-эмитит quad-ы старого
     визуального слота. Если в замороженном кадре на этом слоте был нарисован курсор —
     на экране курсорный блок там, где курсор стоял при уходе со вкладки.
   Усиление: cache-miss строка с `slot < work_start` получает `EmitRetained` даже БЕЗ
   превышения бюджета (`budget.rs:108`: в `Build` попадает только `slot >= work_start`).
   Если уход со вкладки случился на кадре с deferral (`resume_row > 0`), часть фантомных
   строк гарантирована независимо от скорости кадра возврата.
5. Самоисправление: `deferred_any` → `schedule_budget_repaint` (`pane.rs:884-888`), ротация
   доходит до всех строк за ограниченное число кадров (`budget.rs:116-119`; тест
   `rotation_starvation_does_not_happen`). Кратковременность фантома совпадает с тем, что
   пользователь не сообщал о зависшем навсегда курсоре.

## 3. Согласование с симптомом (нарратив поверх подтверждённой механики; INFERRED)

Фантом «вверху» требует, чтобы на момент заморозки курсор стоял в верхней части экрана, а к
моменту возврата ушёл вниз. Естественный сценарий: вкладку оставили сразу после `clear` или
выхода из fullscreen-программы, когда промпт (и курсор) стоит у верхней кромки; за время
долгого простоя скрытый вывод (долгая команда, `claude` и т.п.) прокрутил контент и увёл
реальный курсор вниз. Кадр возврата: свежий курсор внизу у промпта (§2.4a), фантомный блок
вверху (§2.4b) — в точности «ввод наверху, приглашение внизу».

## 4. Класс бага шире вкладок

Тот же инвариант нарушается внутри одной активной панели без всяких вкладок: при перемещении
курсора со строки A на строку B ключ строки A меняется (`cursor: Some → None`,
`render/mod.rs:90-92`), строка A становится cache-miss, но не получает `must_build` (она уже
не строка курсора и может быть не ротационной) — при просроченном дедлайне (или
`slot < work_start`) она эмитит retained-quad со старым курсорным блоком до прихода ротации.
Вкладочная заморозка лишь делает дефект устойчивым и заметным. Фикс должен лечить инвариант
«retained-строка не имеет права содержать курсорный блок, которого больше нет», а не
вкладочный частный случай.

## 5. Следствия для фикса

- Кандидат №2 исходного отчёта (флаг «здесь был нарисован курсор» в `RetainedRow` + форс
  `Build` для таких слотов отдельно от `cursor_row_slot`) — верен, минимален и закрывает ОБА
  случая: вкладочный (§2) и внутрипанельный (§4).
- Кандидат №1 исходного отчёта (сузить `quad_generation` / per-pane генератор) данный баг НЕ
  лечит: он происходит при полном отсутствии bump'а, когда штамп совпадает. Сузление лишь
  сократит частоту тяжёлых full-rebuild кадров.
- Дополнительная опция: включить в `RetainedStamp` y-позицию курсора на момент ретейна —
  несовпадение при любом вертикальном сдвиге курсора → полный rebuild. Грубее кандидата №2
  (лишние full-rebuild при каждой ходьбе курсора), вероятно избыточна.

## 6. Ограничения

- Подтверждение — чтение кода на `7cd27f37e`; живого повторения с логом конкретного кадра нет
  (как и в исходном отчёте). Все «OBSERVED» здесь означают «подтверждено кодом», а не рантаймом.
- Тип установленной сборки (release/debug) не проверялся: аргумент «debug-сборка регулярно
  пробивает 40 мс» (комментарий `pane.rs:380-386`) для установленного бинарника остаётся
  HYPOTHESIS. Для самого механизма достаточно сдвига курсора между слотами за время простоя —
  превышение бюджета лишь расширяет набор фантомных строк (см. усиление в §2.4).
- Вопрос «переживает ли фантом дольше нескольких кадров» не исследовался: код гарантирует
  самоисправление (§2.5), сбоев `schedule_budget_repaint` не искали.
