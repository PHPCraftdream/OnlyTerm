- **#502** (P1, the most important fix): `ProcessGpuContext::get_or_init` could cache an
  already-lost GPU device as healthy if the device was lost *during* `Self::new()`, before the
  global `CONTEXT_VERSION` counter's post-init read happened -- a genuine, if rare, race that
  survived the prior two review rounds. Replaced the global version counter entirely with a
  per-context `lost: Arc<AtomicBool>` flag set by that specific context's own device-lost
  callback, which is correct by construction regardless of timing (no counter to race against).
  Commit `3195939de`.
- **#503**: `WindowEvent::Destroyed` never called `webgpu.mark_stale()` (unlike the sibling
  in-place-rebuild code path, which already did), so a render thread that outlived window
  close (e.g. stuck in a hung driver call, since it holds its own separate `Arc<WebGpuState>`)
  could let a late device-lost event try to notify an already-destroyed window. Added the same
  `mark_stale()` call to `Destroyed`, plus a defensive copy in `TermWindow::drop` for the case
  where `Destroyed` never fires. Commit `53f1ae975`.
- **#504**: `register_device_lost_subscriber` always pushed unconditionally; dead entries were
  only pruned inside the (possibly-never-fired) device-lost callback, so the registry could grow
  by one `Window` clone per window ever opened, unbounded over a process's lifetime. Added
  `retain(subscriber_is_alive)` before each push. Commit `d3a7fe44e`.
- **#505**: the SeqCst-upgrade regression test from the prior round
  (`back_pressure_drops_second_frame_while_in_flight`) was single-threaded and copied the
  ordering logic by hand, with stale `Release`/`AcqRel` constants left in the copy -- a real
  regression to weaker orderings in production would not have failed this test. Extracted the
  ordering-critical logic into three testable free functions
  (`in_flight_is_set`/`mark_repaint_pending`/`finish_in_flight_frame`), had both
  `RenderThreadHandle` and `submit_one_frame` call them directly (no behavior change), updated
  the existing test to call the real helper instead of a copy, and added a new two-real-OS-thread
  stress test (100k trials via a `Barrier`-synchronized litmus pattern) that races the GUI-thread
  and render-thread sides of the handshake against each other and asserts neither ever misses the
  other's update. Commit `9aef1641d`.
- **#506**: the `--start-conf` startup-command send-failure log line included the full command
  text, which can contain tokens/passwords/credential URLs, written to a long-lived per-PID log
  file that could end up in a bug report. Replaced with tab/command index + byte length. Commit
  `23c245062`.
