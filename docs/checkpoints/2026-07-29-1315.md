## Decisions
- zstd → flate2 (pure Rust), но затем сжатие в codec ПОЛНОСТЬЮ отключено — raw оказался быстрее (~1.55х) даже после фикса производительности сжатия, экономия трафика (47х) не оправдывает CPU-цену для этого протокола.
- Никакого Rc→Arc-sweep для потоковой модели рендера — вместо этого render-поток должен сам строить свой Rc-мир из Send-safe seed-данных (эта идея пока не реализована — задачи под неё удалены вместе с планом 192-200 и ещё не воссозданы под per-tab).
- unsafe self-referential struct в renderstate.rs переписан на safe scoped-closure API — оказалось, что unsafe был ИЗБЫТОЧЕН (не только для потоковой модели, но и вообще), включая WebGpu-ветку, после проверки реальных сигнатур glium/wgpu.
- **Пользователь только что решил (ответ ещё не обработан в задачах)**: архитектура рендер-потоков должна быть per-tab (настоящий поток на каждую вкладку, включая неактивные), а НЕ per-window, вопреки более ранней находке агента, что сейчас рендерится только активная вкладка. Причина/мотивация пользователя не уточнена явно (возможно превью неактивных вкладок или желание убрать задержку переключения) — стоит уточнить при возобновлении, если не очевидно из контекста.
- При зависании production-сессии — НЕ трогать чужие процессы без явного разрешения (пользователь явно просил "у меня много важных рабочих сессий - ничего нельзя трогать. только свои трогай"); dev-сборки собираются и тестируются ТОЛЬКО в `D:\dev\rust\onlyterm\target\release`, установка в `C:\Program Files\OnlyTerm` требует отдельного явного разрешения.
