The first half was a live bugfix cycle driven by the user running the built binary. Each
bug was found from actual evidence -- logs, measurements, recordings -- rather than by
guessing, and that repeatedly overturned a plausible-sounding first theory:

- **Ctrl+J did nothing in Codex CLI.** Its win32-input-mode sequence carried `Vk=0, Sc=0`
  where Windows Terminal sends `Vk=74, Sc=36`. `SendChar` built its synthetic key event
  with zeroed raw fields, and ConPTY/crossterm recover the character via
  `ToUnicode(vk, sc, ..)`, which fails outright for `vk == 0` -- so the keypress was dropped
  before the app saw it. Ctrl+C worked all along only because its handler hardcoded the real
  VK_C/scan pair. Fixed with `PhysKeyCode::to_win32_key_codes` plus one shared
  `synthetic_key_down` constructor for all three assignments.
- **Ctrl+Enter** was rebound to the Ctrl+J chord: a faithful modified-Enter is what it
  literally is, but nothing acts on one (Codex ignores it, so does Windows Terminal).
- **Shift+Enter** turned out not to be a code bug at all: the user's own `.onlyterm.ktav`
  had `{ key: Enter, mods: SHIFT, action: { SendKey: { key: Enter } } }` shadowing it. With
  the user's explicit permission those two lines were removed (backup at
  `~/.onlyterm.ktav.bak-before-enter-chord-fix`). All three chords then confirmed live.
- **The grey-background-on-paste bug in PowerShell** was the same defect as Cyrillic showing
  as `?`: the system code pages are OEM 437 / ANSI 1252, neither of which can represent
  Cyrillic. Output escapes this (a console app writing to a real console goes through
  `WriteConsoleW` in UTF-16, verified by recording a session with `onlyterm record`); what
  does not is everything byte-oriented -- console input, hence pasted text. PowerShell now
  starts on UTF-8, first only from the New Tab Options dialog and then, at the user's
  request, centrally from `Config::apply_cmd_defaults`. User confirmed both symptoms gone.
- **The version overlay's "Press Ctrl+Shift+C to copy"** could never have worked:
  SHIFT|CTRL C is a global binding to `CopyTo(Clipboard)`, consumed before the keypress
  reaches the overlay pane, and it copies the (empty) selection. Replaced with a clickable
  Copy button.
- **The admin tab indicator rendered nothing** because `Tab::set_elevated` had zero call
  sites workspace-wide -- everything else was wired, the flag was simply never set.
- A reported `--start-conf` defect ("third tab's second command doesn't run") was
  reproduced and found not to be ours: `git branch` in that repo has 46 branches, so git
  pages, and the pager eats the pre-typed next command. Proven with a two-tab experiment
  (`git branch` vs `git --no-pager branch`).

## Decisions

- Bound Ctrl+Enter to the Ctrl+J chord rather than to `SendEnterOrNewline(CTRL)`. A
  faithful modified-Enter is what the chord is, but hardly anything acts on one; Ctrl+J is
  the universally understood "insert a line feed". The faithful action stays available via
  config.
- Assigned `[Console]::OutputEncoding`/`InputEncoding` rather than running `chcp 65001`:
  those setters call SetConsoleOutputCP/SetConsoleCP *and* rebuild the cached reader and
  writer, where `chcp` alone leaves PowerShell encoding with the code page it captured at
  startup -- console and shell then disagree, which is worse than either alone.
- Chose lowercase `--start-conf` values (`above_normal`) over the PascalCase used elsewhere
  in the config, at the user's explicit choice. Implemented by replacing ProcessPriority's
  derived FromDynamic with a lenient hand-written one, which is strictly more permissive,
  so existing PascalCase configs keep working.
- Split Phase D into three mechanisms rather than one: job objects for non-elevated
  children, a parent-death watchdog for elevated ones, and the domain-registration fix as
  its own independent leak. Rejected a single broad delegation after the user asked for
  research first -- the earlier broad run was killed mid-flight.
- Left the pump hang fix without a regression test, deliberately. The scenario needs the
  pump to be inside `write_all_to_local` when the peer dies and the thread exposes no state
  to synchronise on, so every attempt passed with the fix reverted. A test that cannot fail
  against the bug claims coverage it does not have.
