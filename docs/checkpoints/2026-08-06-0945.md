## Decisions

- Task #407 is NOT closed by the alpha_mode fix — confirmed via direct `wgpu-hal` source inspection that Windows DX12's `SurfaceTarget::WndHandle` surfaces only ever report `Opaque` in `composite_alpha_modes`, so that swapchain was already Opaque pre-fix. The real Windows-specific cause of the reported transparency bug remains unidentified; the `@oh` review's suggested next lead is the `WS_EX_LAYERED`/`WS_EX_TRANSPARENT` placeholder overlay window, not the WebGpu surface itself.
- A cached-flag approach to "is this the process's first window" is unsound across an `await` boundary when the surrounding reconcile logic can run concurrently from multiple call sites; the fix is to evaluate the live predicate (`known_windows` non-empty) at the point of failure, not snapshot it ahead of time. General lesson worth remembering for any future "first vs. subsequent" logic spanning an async boundary in this codebase.
- Chose to run TWO full `@oh` review passes (not one) once the first pass found real, non-cosmetic bugs — a single pass would have left a genuine race condition and window leak in a "fixed" task. Diminishing-returns judgment call: stopped after the second pass's remaining findings were all LOW/INFO severity with no further correctness implications.
- Deliberately did not chase non-Windows packaging staleness (macOS `.dylib`s, Linux RPM/deb Mesa dependencies) discovered as a side effect of the #427 fix — out of scope for this Windows-focused fork's immediate work, no user request to touch other platforms' packaging.
