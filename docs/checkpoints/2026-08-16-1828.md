## Session summary

Two features landed and were pushed to `main` (`d4ea7c58c..4fe252d61`).

**Shell detection (`111869bd7`).** The New Tab Options dialog listed a fixed four shells
regardless of what was installed. Worse, picking "bash" on a machine without Git for Windows
started WSL, because argv[0] was a bare image name and Windows resolves that against System32
before PATH -- where WSL's launcher shim lives. Two menu entries, one program. `Shell::resolve`
now answers with an absolute path or `None`, from explicit well-known locations only;
`available_shells()` drops what resolved to nothing and collapses any two names landing on the
same executable. `wsl.exe` exists even where no distribution does, so registered distros are
read from the `Lxss` registry key rather than by running `wsl.exe --list` -- this list is built
on the dialog's render path and a process launch there would be paid per frame.

**`--choose-tab` (`1045046a2`, `a3da7e1f9`, `4fe252d61`).** OnlyTerm can now start with no tab
at all, showing only the New Tab Options dialog; the tab appears when the user picks a shell and
presses Run, and dismissing the dialog ends the process. What keeps that window alive is a mux
`Activity` -- an empty mux is pruned and terminates the app, and both the prune and the
`MuxNotification::Empty` handler check that counter first. The `Activity` the `MuxWindowBuilder`
holds is useless for this: it dies right after `WindowCreated` is sent.

The plan (`docs/plans/2026-08-16-startup-tab-chooser.md`) turned out to be **wrong in two
places, both found by measurement rather than reasoning.** It predicted `CurrentPaneDomain`
would break without a pane; in fact `resolve_spawn_tab_domain` already falls back to
`default_domain()` when `pane_id` is `None`, so no change was needed there. And it asserted
"TermWindow already tolerates having no tabs" -- true for construction and painting, false for
input: both keyboard entry points and the mouse entry point returned early on a missing pane,
before their modal dispatch, so the dialog was deaf and blind. `spawn_tab_or_window` also read
geometry off the active tab and failed with "window N has no tabs". All three are fixed in
`1045046a2`, which is deliberately a separate commit because it repairs any tabless window, not
just this feature.

**Installer (`4fe252d61`).** `ci/dev-install.ps1` never touched the shell context menu, so a dev
install left stale entries. It now registers the three scopes the Inno installer does, plus a new
"OnlyTerm Run As" that launches with `--choose-tab`. That request exposed my own error: I had
declared `--choose-tab` as conflicting with `--cwd`, reasoning that both say *what* to launch.
Wrong -- `--cwd` says *where*, and the menu entry passes the clicked folder. Conflict removed,
cwd plumbed through the chooser slot into the `SpawnCommand`.

**Delegation went badly and is worth remembering.** Three crush runs produced five fabricated

myself. A PowerShell string that failed to terminate still passed `Parser::ParseFile`, because

variable costs one full rebuild of local crates and nothing else.

## Decisions

- Application-visible shells are resolved to absolute paths from known locations, never left to
  process-launch resolution. That is what makes "two names, one program" impossible by
  construction rather than by the reader trusting a table.
- WSL counts as installed only when a distribution is registered, read from the registry. Chose
  that over `wsl.exe --list` because the list is built on the render path; accepted that Docker
  Desktop's own distros count, since telling them apart means guessing from names.
- The tabless-window input/spawn repair is its own commit, separate from the feature that
  exposed it, so it can be reverted or kept independently.
- Dismissal goes through one `perform_dismiss` function that both Esc and the close cross call.
  The mouse path reads the choice and releases its `RefCell` borrow *before* dispatching, since
  `cancel_modal` takes `borrow_mut` on that same cell.
- The Activity moves into the run request rather than dying with the modal. Between "dialog
  dismissed" and "tab present in the mux" the mux is empty; dropping it there reintroduces
  exactly the bug it prevents. Correctness currently rests on both spawn paths sharing one FIFO
  scheduler queue -- documented at the site, because moving the spawn to
  `spawn_with_low_priority` would silently restore "Run quits the application".
