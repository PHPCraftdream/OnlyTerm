символы ✻ (U+273B) и ⏵ (U+23F5), которые рисует Claude Code CLI внутри
терминала, по-прежнему квадратики В НОВОМ окне (после переустановки
release-сборки в 12:33). `ls-fonts --codepoints` (тот же шейпинг +
CPU-растеризация, что у живого рендера) резолвит их корректно — но это
использует `GlyphCache::new_in_memory` → `ImageTexture` (чисто CPU-side
заглушка), а НЕ реальный `WebGpuTexture`/`SrgbTexture2d`, так что успех
`ls-fonts` не доказывает GPU-side корректность. Пользователь лично
подтвердил эмпирически: при изолированном запуске (`--config-file` с
только `front_end: OpenGL`, отдельный `--class`, не трогая основной
конфиг) символ рисуется КОРРЕКТНО. Это окончательно сужает причину до
WebGpu-специфичного бага (атлас/upload текстуры/семплинг в шейдере), не
шрифтов. Начато сравнение `WebGpuTexture::write` (queue.write_texture,
формат `Rgba8UnormSrgb`) с OpenGL-эквивалентом `SrgbTexture2d::write`
(glium) — оба используют sRGB и внешне выглядят симметрично на уровне
формата; расследование не завершено, следующий шаг — сравнить
`Atlas::allocate`/рост атласа и путь семплинга в `shader.wgsl` против
`glyph-frag.glsl`. Пользователь попросил взять это в приоритет сразу
после закрытия текущего раунда.
