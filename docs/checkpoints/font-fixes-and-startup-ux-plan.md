# Checkpoint — 2026-08-05 [font-fixes-and-startup-ux-plan]

## Session summary

OnlyTerm — Windows-ориентированный форк wezterm со снятым скриптовым слоем
(конфиг ktav, ни Lua, ни rhai). Эта часть сессии продолжает большой
babygoal-цикл (распил файлов + чистка clippy, полностью завершён и
закоммичен ранее) и последующее исправление семи находок ревью `@oh`
(#373–#379, все закрыты и закоммичены в предыдущей части сессии).

**Основной объём этой видимой части сессии — две крупные фичи по прямому
запросу пользователя, обе доведены до коммита:**

1. **Горячее обновление + перенастройка чекера обновлений.** Пользователь
   спросил, есть ли у нас (не у npm) механизм горячего обновления
   бинарника — переименовал `ci/dev-install.ps1` со схемы «убить процессы →
   скопировать» на схему rename-and-replace (`Install-FileHotSwap`):
   переименовать текущий файл в `<имя>.old`, положить новый под исходным
   именем — работает, потому что Windows по умолчанию открывает
   исполняемые файлы с `FILE_SHARE_DELETE`, так что переименование
   работающего файла разрешено, а уже запущенные процессы продолжают
   работать со старыми (переименованными, но не удалёнными) данными.
   Заодно этот скрипт наконец закоммичен — был неотслеживаемым с начала
   сессии. Отдельно перенастроен `crates/wezterm-gui/src/update.rs`: чекер
   обновлений стучался в `api.github.com/repos/wezterm/wezterm` (upstream),
   теперь — в `api.github.com/repos/PHPCraftdream/OnlyTerm` (наш репозиторий,
   найден через `git remote -v`); ссылка «что нового» теперь берётся из
   `html_url` самого релиза GitHub API, а не собирается вручную под
   несуществующий для наших тегов `wezterm.org/changelog.html`. Коммиты:
   `7507e83d0` (update.rs), `26d6b0a94` (dev-install.ps1).

2. **#370/#371 (баги из ревью `@oh`, найденные ранее) + #381 (новый баг,
   обнаружен по ходу).** #370 (tofu на U+23BF и подобных символах) закрыт
   бандлингом Noto Sans Symbols + Noto Sans Symbols 2 как built-in
   fallback-шрифтов (лицензия OFL 1.1, та же что у уже забандленных
   шрифтов — согласовано с пользователем явным вопросом). #371 (тонкий
   шрифт на WebGPU) — прежняя гипотеза («нет dual-source blending для
   субпикселя») оказалась НЕВЕРНОЙ: subpixel-режим выключен по умолчанию,
   а растеризатор swash физически не умеет LCD-сглаживание (FreeType в
   форке вообще нет). Настоящая причина: OpenGL намеренно блендит в
   gamma-пространстве (`outputs_srgb: true` + ручной `to_srgb()` в
   glyph-frag.glsl), а WebGPU писал в sRGB-поверхность без ручной
   гамма-коррекции, из-за чего GPU автоматически (и физически корректно, но
   визуально «тоньше») блендил в linear-пространстве. Фикс — привести WGSL
   к тому же способу блендинга: `to_srgb()` в шейдере + non-sRGB view
   поверхности. **Не подтверждено визуально** — GUI не запускается в этом
   headless-окружении (стабильный stack overflow, ПОДТВЕРЖДЁН как
   предсуществующий на чистом HEAD через `git stash`, не моя регрессия) —
   стоит проверить глазами при обычном запуске.

   В процессе тестирования #370 через `onlyterm-gui.exe ls-fonts` найден
   **новый баг #381**: один и тот же запрос на одни и те же кодпоинты
   давал НЕДЕТЕРМИНИРОВАННЫЙ результат — иногда U+2702 (✂, Dingbat)
   резолвился в правильный шрифт (Noto Sans Symbols 2), иногда в tofu.
   Расследовано с временной eprintln-диагностикой (полностью убрана перед
   коммитом) до двух причин: (а) бандленный `NotoColorEmoji.ttf` реально
   маппит U+2702 на ненулевой glyph_id и по `swash::Charmap::enumerate`
   (используется для `compute_coverage`), и по `Charmap::map` (реальный
   lookup) — но при настоящем шейпинге рендерится как notdef, вероятно
   потому что это компонент лигатуры/ZWJ-последовательности, подставляемый
   через GSUB, а не самостоятельный символ; (б) сортировка кандидатов
   fallback-шрифтов была включена только при опциональном
   `sort_fallback_fonts_by_coverage` (по умолчанию `false`!) — то есть по
   умолчанию порядок кандидатов определялся порядком обхода `HashMap`
   (`FontDatabase::by_full_name`), рандомизированным на процесс. Фикс:
   сортировка теперь ВСЕГДА выполняется (не только опционально), с
   приоритетом non-emoji шрифтов на равном покрытии + финальный
   детерминированный tie-break по имени шрифта. Проверено 15 подряд
   запусков — стабильно корректно; легитимный emoji-only fallback (U+231B)
   по-прежнему резолвится через Noto Color Emoji. Коммиты: `67612a1f1`
   (#370, бандлинг Noto Sans Symbols), `2409ecf26` (#371, WGSL srgb),
   `fa13c19cc` (#368, отдельный баг — snapshot-тесты wezterm-surface,
   зависевшие от feature-unification фичи `appdata`), `524f941f9` (#381,
   детерминированная сортировка), `a9cd9c566` (changelog на #370/#371).

## Decisions

- Горячее обновление реализовано через rename-and-replace (`Install-FileHotSwap`
  в `ci/dev-install.ps1`), а не остановку процессов — обоснование: Windows
  разрешает переименовывать исполняемый файл, за который держится хендл с
  `FILE_SHARE_DELETE` (стандарт по умолчанию для запущенных `.exe`/`.dll`).
- Для #370 выбран Noto Sans Symbols + Symbols 2 (OFL) вместо GNU Unifont —
  явный выбор пользователя по лицензионным соображениям (не вносить новую
  категорию лицензии GPL+exception, раз весь остальной набор шрифтов уже
  на OFL/Apache-2.0).
- Для #371 отвергнута исходная гипотеза (dual-source/subpixel blending) в
  пользу более простого и куда менее рискованного фикса (привести
  gamma-пространство блендинга WGSL к тому же, что уже работает в GLSL) —
  решение не задавалось пользователю как выбор, а является прямым
  результатом расследования, которое опровергло исходную гипотезу.
- Для #381 сортировка кандидатов fallback-шрифтов сделана БЕЗУСЛОВНОЙ
  (не только при опциональном `sort_fallback_fonts_by_coverage`) — решение
  принято потому что два из трёх ключей сортировки являются фиксом
  корректности, а не предпочтением качества, и оставлять их под опциональным
  тумблером означало бы оставить баг воспроизводимым при дефолтной
  конфигурации (флаг по умолчанию `false`).
- Задача про плавный старт окна декомпозирована на 4 строго
  последовательные подзадачи (не параллельные) — каждая содержательно
  зависит от результата предыдущей (лоадер должен рисоваться уже в
  правильном размере окна; fade нужен готовый лоадер).
