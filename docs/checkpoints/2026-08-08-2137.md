## Decisions

- Chose to auto-detect the foreground process (`claude.exe`) and disable bidi per-pane, over a manual keybinding toggle or a global `bidi_enabled: false` -- fully automatic, no user action needed, and the detection mechanism (`Pane::get_foreground_process_name`, 300ms-TTL cached) already existed in the codebase for `skip_close_confirmation_for_processes_named`.
- Chose `dunce::canonicalize` over plain `std::fs::canonicalize` for resolving `--start-conf`'s relative `root_dir` -- plain canonicalize's `\\?\`-prefixed Windows verbatim path form is rejected by `cmd.exe` as a starting directory; caught by a live smoke test, not by unit tests, and added a dedicated regression test for the `\\?\` prefix specifically.
- Chose F2 (matching Windows Explorer's rename convention) + double-click on the tab bar as the rename triggers, explicitly WITHOUT a native context menu (user's explicit request) -- reuses the existing (previously dead-since-the-rhai-removal) `PromptInputLine` overlay machinery rather than building a new UI from scratch.
- Delegated the non-Windows-platform-code removal + SSH/TLS removal to a `crush` sub-agent as one session (`remove-nonwindows-ssh`) rather than splitting into two separate delegations; in hindsight this was fine since Phase B turned out to be a no-op (already done earlier), but the shared-file collision (crush's `git commit` swept up two of my own already-edited-but-uncommitted files, `Cargo.toml` and `command_def.rs`, into its Phase A commit) is a concrete lesson: a `crush` run's own commit step is not scoped to only the files it touched by design in this codebase, so running it in a working tree with substantial unrelated uncommitted changes has entangled-commit risk, not just parallel-run collision risk.
