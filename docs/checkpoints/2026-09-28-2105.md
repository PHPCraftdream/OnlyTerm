prompt after tab switches (ConPTY wrap marks/reflow on resize, commit `4c65aa030`,
tag `v0.0.30-alpha`, CI green). The user then asked for a performance audit of the
project; the audit (release measurements via a temporary probe) found that applying

## Decisions

- Chose GUI-side lazy tab resize (tracker of requested + settled size, sync at
  apply_dimensions, activate_tab and every paint) over resizing inside mux
  `Window::set_active_without_saving`, because the latter runs under the windows
  write guard and deadlocks with the synchronous TabReflowed subscriber.
- Chose squash-merging each agent branch into one reviewed commit on main over
  merge commits, to keep "one commit per task" and room for root fixes.
- Kept pure-perf refactors behaviour-identical, proven by differential tests against
  the old algorithm, with mutation checks for teeth; accepted one intended
  difference in A1 (a VecStorage pruning quirk that orphaned a wide cell's
  continuation no longer triggers for clustered lines).
- Chose one-lock pane snapshot with changed rows taken before the hyperlink pass,
  preserving the old selection-invalidation semantics.
