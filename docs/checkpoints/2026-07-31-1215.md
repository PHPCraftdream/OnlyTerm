The 5 first-round fixes:
- `715680f97` — fixed a real cross-window race in `OPENGL_FALLBACK_RELAY` (a single process-wide `thread_local!` slot let two windows falling back to OpenGL concurrently clobber each other, destroying the wrong window and killing its panes' processes). Moved the relay onto a per-window `Rc<RefCell<...>>` field.
- `ac32849dc` — `TermWindow::created()` only ever panicked on a `RenderState::new` failure, making two graceful-recovery call sites dead code and turning a renderer-rebuild failure into a full process abort. Changed to return a real `Err`.
- `3336ffc78` — the wgpu device-lost callback had no guard against firing for an already-abandoned device, risking dragging a permanently-OpenGL-fallen-back window back into the WebGpu rebuild dance. Added an `is_current`/`mark_stale` liveness flag plus a `permanently_on_opengl` flag checked at the top of the shared recovery entry point.
- `f11c1481b` — the per-tab frame-build budget's cache-miss skip path left rows blank forever on an idle window because nothing scheduled a follow-up repaint. Added `update_next_frame_time` at the budget-trip site.
- `423c294a2` — two unrelated producers (a genuine terminal-lock timeout, and the per-frame render-budget signal) wrote to the same shared `AtomicBool`, so the render-budget path's ~60/sec writes silently clobbered a real hang signal for the active tab. Split into two independently-owned cells, OR'd only at the read site.

After all 5 were fixed, a SECOND, smaller `@oh` review pass (agentId `ac12ed0114aff7259`) was dispatched specifically over just those 5 fix commits, to check they didn't introduce new bugs or weaken each other. This is a new practice this session -- reviewing the fixes themselves, not just the original work. It found the batch overall sound (no panics, leaks, borrow errors, or ordering bugs in the new code) but surfaced 3 more real, narrower issues, which were independently spot-checked by the orchestrator by reading the actual code (not just trusting the review's prose) before being turned into 3 more tasks (#271-#273) and fixed the same way:
- `ff9105547` (task #271, medium) — task #268's repaint-scheduling fix only worked when the window was focused (`paint_impl` only consumes `has_animation` inside `if self.focused.is_some()`), so an unfocused window's skipped rows still stayed blank forever. Added an unconditional, focus-independent `schedule_budget_repaint` mechanism.
- `362979e3e` (task #272, medium) — task #266 made a previously-panic-guarded branch reachable, and that branch closed the window immediately on a `RenderState::new` failure during rebuild instead of retrying through the circuit breaker/OpenGL fallback like its sibling branch already did. Routed it through the same `attempt_renderer_rebuild_or_close` path.
- `3709c088c` (task #273, low) — task #269's new `render_budget_exceeded` cell was a plain sticky bool that only got cleared by the render loop, which stops running entirely for a pane whose tab is no longer active -- so a pane could get permanently mis-flagged as unresponsive after its tab was switched away from. Changed to an expiring `Instant`-based signal (1-second window) instead of a sticky bool.
