# Checkpoint — 2026-07-24 18:00 [onlyterm-decouple-from-C]

## Session summary

Продолжение и завершение большой инициативы «убрать весь C/C++/asm из
onlyterm», начатой в предыдущих сессиях. К началу этой сессии уже были
завершены cairo→tiny-skia и удаление SSH/TLS-mux. В этой сессии закрыты
оставшиеся два трека целиком:

1. **freetype+harfbuzz→rustybuzz+swash** — H0-H5 полностью завершены.
   Дефолтный шейпер — `RustybuzzShaper`, дефолтный растеризатор —
   `SwashRasterizer` (включая pure-Rust COLR/COLRv1 через
   `onlyterm-font/src/rasterizer/colr_paint.rs` на `ttf-parser`, заменивший
   HarfbuzzRasterizer). `deps/freetype`, `deps/harfbuzz` и все связанные
   FFI-обёртки (`ftwrap.rs`, `hbwrap.rs`, `shaper/harfbuzz.rs`,
   `rasterizer/harfbuzz.rs`, `rasterizer/freetype.rs`) удалены. По пути
   найден и исправлен реальный deadlock (**BUG8**: `Configuration::reload()`
   держал мьютекс во время рекурсивного вызова через `SETUP_FUNCS` —
   пофикшено переносом `Config::load()` до захвата лока), а также
   измерена и исправлена ~48% регрессия производительности перечисления
   шрифтов (**PERF1**: `.ttc`-коллекции перечитывались с диска N+1 раз
   вместо одного).

2. **Lua(C)/mlua→rhai** — L1-L7 полностью завершены. По пути найдены и
   закрыты ДВА архитектурных пробела плана (аналогично H3.5 из
   предыдущей сессии): **L4.5** (config-loading фактически всё ещё звал
   `make_lua_context`, хотя rhai-инфраструктура была построена параллельно)
   и **L4.6** (event-callback мост `onlyterm.on`/`emit` всё ещё держал
   companion `mlua::Lua`, так как `rhai::Engine`/`AST` не `Send` без
   feature `sync` — решено message-passing подходом: через канал
   передаётся не сам `Engine`, а `RhaiEventScript` с исходным текстом,
   движок пересобирается на главном потоке). Затем найден **третий**
   живой потребитель mlua — debug-REPL оверлей (Ctrl+Shift+L,
   `onlyterm-gui/src/overlay/debug.rs`) — портирован на rhai отдельной
   задачей **L4.7**. После этого **L5** (вычистка mlua/luahelper из
   workspace) прошла чисто. **L6** — написан migration guide
   (`docs/migration-lua-to-rhai.md`) и обновлена документация. **L7** —
   финальная верификация (полный `cargo test --workspace` зелёный, живая
   проверка реального `.wezterm.rhai`-конфига и dedicated
   error-сообщения для старого `.wezterm.lua`).

3. **Хвостовые задачи**: **Z1** — `rusqlite`/`sqlite-cache` в

## Decisions

- `redb` выбран вместо `minisqlite`/`fjall` для Z1 — простой embedded
  ACID key-value store, 0 unsafe в ядре, кросс-платформенный; minisqlite
  не собирался на Windows и не публиковался на crates.io.
- git2/libgit2 полностью удалён вместе с фичей авто-клонирования
  git-плагинов (не заменён на pure-Rust git-библиотеку) — решение
  пользователя в духе более раннего решения про SSH: «не нужно в
  терминале».
- Event-callback мост (L4.6) реализован через message-passing
  (`RhaiEventScript`, пересборка `Engine` на главном потоке), а не через
  включение rhai `sync`-feature — избежали каскадных Send+Sync
  требований на все 63 метода/4 CustomType в mux и все lua-api-crates.
- Debug-REPL оверлей (L4.7) — портирован на rhai, а не удалён и не
  оставлен на mlua — консистентно с общим направлением инициативы.
- Методология реализации переключена с `@sh`-под-агентов на `crush run`
  в середине сессии по прямой инструкции пользователя, затем обратно на
  `@sh` в конце — текущий режим на конец сессии: **`@sh` (Agent-тул)**.
- #7965: не найдя точной причины, выбрано превентивно отвердить
  единственного правдоподобного кандидата (procinfo tree) даже без
  100% доказательства причинности — низкий риск, закрывает целый класс
  багов.
