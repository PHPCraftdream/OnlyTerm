**What happened, in order:** Picked up a `samply record` CPU profile that had been captured against a debug `onlyterm-gui.exe` (PID 1528) while the user ran Claude Code inside it. Symbolicated it via `samply load --no-open` + direct HTTP calls to its local symbol server (`/symbolicate/v5`, `memoryMap`/`stacks` request format), then parsed the gzipped Firefox-Profiler-format JSON with a small Python script (`ci/analyze_profile.py`, uncommitted) to compute self-time and inclusive-time per function, filtered to the main GUI thread to cut through ~350 mostly-idle worker threads.

Found two real, roughly equal-sized (~5% of main-thread CPU time each) hot paths, both stemming from full grapheme-cluster scans (`finl_unicode`) that should have been cached but weren't:
1. **Task #462**: `Pane::apply_hyperlinks()` ran unconditionally every frame, and `Screen::for_each_logical_line_in_stable_range_mut`'s wrap-boundary walk called `Line::last_cell_was_wrapped()` with zero caching. Implemented directly (not delegated) after three crush rounds each shipped a subtly incomplete/incorrect cache design (first: cache never populated from the read path; second: cache correctness depended on manually finding every cell-mutating method, several of which were missed). Final design: seqno-keyed memoization using two `AtomicBool`/`AtomicUsize` fields on `Line`, valid iff the stored seqno matches `self.seqno` — reuses the same "any mutation bumps seqno" contract the codebase already trusts for `shape_hash_for_line`'s cache, so no per-mutation-site invalidation bookkeeping is needed. Commit `d85a5280f`. Also fixed a stale, unrelated pre-existing test failure found along the way (`wezterm-term::test::csi::test_789` — a snapshot never regenerated after `Line` got a manual `Debug` impl that intentionally omits `appdata`), commit `a694a1adc`.
2. **Task #439**: `shape_hash_for_line`'s existing seqno-keyed cache could never hit — the cache handle lived on the `Line` via `appdata` (a `Weak`), but the render path (`Pane::get_lines`) only ever sees a throwaway per-frame clone, and `Line::clone` copies the `Weak` without the clone's own mutations propagating back to the original in `Screen`. Measured (not assumed) hit rate on the old cache: 0%. Delegated to crush (two rounds: first shipped a real fix but with a vacuous test that reimplemented the cache logic instead of exercising the real `LfuCache`/production function, an unmeasured "~95% expected" claim, and un-cleaned dead code; second round fixed all three). Final design: cache moved to `TermWindow`, keyed by `(pane_id, stable_row)`, with the lookup/store decision extracted into a free function (`shape_hash_lookup`) so tests can exercise the exact production logic with a real `LfuCache` and a call-counting closure. Measured after-fix hit rate: 98% (2450/2500 over 50 simulated frames of 50 unchanged lines). Old `CachedLineState`/`line_state_cache`/`LruCacheWithMetrics` machinery removed outright rather than left as dead weight. Commit `f12df7bbb`.
