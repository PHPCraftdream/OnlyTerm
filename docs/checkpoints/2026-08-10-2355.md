## Decisions

- Migrated `PHPCraftdream/OnlyTerm` off the GitHub "fork" relationship by creating a brand-new non-fork repo and mirror-pushing history, rather than requesting GitHub Support detach the fork (faster, user-approved, old fork kept as `OnlyTerm-legacy-fork` for safety).
- Squashed all upstream wezterm history (8630 commits) into one root commit via manual `commit-tree`+`rebase --onto` rather than a tool like `git filter-repo` for this step, since it needed to preserve the fork's own 433-commit structure exactly (including internal merge commits) on top of a single synthetic root.
- For the later asset-history purge, deliberately did NOT operate on the working directory in place — cloned to an isolated temp directory, ran `git-filter-repo` there, verified tree-hash identity, pushed from the clone, then synced the working directory via `fetch`+`reset --hard` only after verification. Chosen over in-place rewriting to eliminate any risk to the live working tree.
- Chose full Windows-only cleanup (deleting real Unix/macOS implementations, not just hiding them further behind cfg) over leaving the `#[cfg(unix)]` code in place as "already inert" dead weight, per explicit and repeated user confirmation ("полный снос кода", "делай зачистку").
- Kept a few genuinely inert-but-harmless config surface areas as-is rather than also stripping them (e.g. `IntegratedTitleButtonStyle::MacOsNative`/`Gnome` enum variants remain parseable, matching pre-existing `Gnome` behavior) — judged as user-facing config-format stability, not dead code, distinct from the OS-conditional *logic* that was removed.
- Did not purge history for the large binaries still shipped at HEAD (opengl32.dll, demo mp4s, NotoColorEmoji duplicates, bidi test data, unicode_names.rs) even though they dominate `.git` size — that would require a "keep only latest version" rewrite, not simple path removal, and was out of scope for what the user asked to purge (only the *deleted* macOS/Linux assets).
