**Thread A — Startup UX cluster (font crashes, flicker, slow start), now fully closed.** A real user-reported chain: symbol U+203B (※) failed to render + a Windows toast popped up ("Font problem" — this turned out to be *intentional*, not a bug: `onlyterm-font/src/fallback.rs` shows a toast whenever `warn_about_missing_glyphs` fires). Root cause traced through several layers: the user's live config had `font_locator: ConfigDirsOnly` + `font_dirs: [C:/Windows/Fonts]`, but a separate, undocumented flag `search_font_dirs_for_fallback` (default `false`) meant `font_dirs` was scanned but never actually consulted for fallback resolution (task #419). I added `search_font_dirs_for_fallback: true` to the user's live `.onlyterm.ktav` with explicit permission — which then triggered a real, reproducible `EXCEPTION_STACK_OVERFLOW` crash (confirmed via `minidump-stackwalk`, installed via `cargo install`, against dumps in `C:\CrashDumps\OnlyTerm\`) when the font-dirs scan parsed all of `C:/Windows/Fonts` (task #422, root cause NOT yet fixed in code — only mitigated). Mitigated first by narrowing `font_dirs` to a small folder with just `seguisym.ttf` — which then broke the user's explicit `font: [{ family: Lucida Console }]` (lucon.ttf wasn't in that folder either) (task #423, fixed by adding lucon.ttf too). Eventually found the actually-correct fix: switch `font_locator` from `ConfigDirsOnly` to `Gdi` (the real system font locator) and drop `font_dirs`/`search_font_dirs_for_fallback` entirely — this resolved ※, CJK (U+6F43), Lucida Console, and sidesteps the stack-overflow-prone code path all at once, and is what's live in the user's config now. While investigating, found and fixed a real code bug unrelated to the user's specific config: `FontConfigInner` never rebuilt its `locator` when `font_locator` changed at runtime — only `font_dirs` was rebuilt in `config_changed()` (task #424, commit `9ec1fd597`). Also fixed task #405 (startup delay): the real culprit was `resolve_color_scheme()` TOML-parsing all ~1001 bundled color schemes just to find the user's one named scheme (`compute_extra_defaults` measured 2.21s → 14ms after adding `lookup_default_scheme()` with memoization; commit `d6c307753`). Also fixed task #425 (window flicker/black-flash before the first real frame): `TermWindow::created()` tore down the GDI placeholder as soon as the WebGpu render pipeline object merely existed, before any real frame was ever submitted, leaving a ~150-165ms gap where the DXGI swapchain showed undefined content; moved the teardown to `paint_impl` right after a successful `call_draw()` (commit `6196643a6`). Task #407 (white/transparent rectangles with a second background OnlyTerm window) was investigated twice: first hypothesis (DWM minimize/restore animation) was disproven by a control test against plain `notepad.exe` showing the identical artifact — so that specific repro was *not* an OnlyTerm bug. But the user then clarified the real trigger was "at the start of one window while another OnlyTerm window is in the background" — which matches the #425 mechanism almost exactly (the undefined-swapchain gap, made visible as "transparency" instead of a black flash because another window is behind it instead of the desktop). **This is not yet confirmed fixed** — the user needs to install the fresh build (`ci/dev-install.ps1`, hot-swaps binaries without killing running processes) and retest with two windows. Task #426 (new, not yet investigated) is a fresh report: "Unable to load Lucida Console" warnings reappear specifically when the user changes OS font DPI/scaling and then zooms the terminal font size — likely related to `ParsedFont::best_matching_index`'s stretch-matching logic in `onlyterm-font/src/parser.rs` (found two unguarded unsigned subtractions in the `None =>` branches around lines 590-592/605-607 that look like a real bug relative to their guarded siblings at 586/601, but not yet proven to be the actual cause — needs empirical repro, not just code reading).

## Decisions

- Delete OpenGL entirely, including `FrontEndSelection::Software` (which turned out to be GL/Mesa-backed, not independent) — user's explicit call after being shown the tradeoff.
- On WebGpu init/render failure, do NOT fall back to OpenGL (which no longer exists) — instead fail with a clear, well-formed error ("падать красиво по всем стандартам"), never a silent blank window. This is #414's central requirement, not just a mechanical deletion.
- Root-cause fix for the whole font-crash/tofu/warning cluster: switch the user's live config to `font_locator: Gdi`, dropping `font_dirs`/`search_font_dirs_for_fallback` — rejected the earlier narrow-font_dirs mitigation as merely a stopgap once the real system-locator fix was found.
- When a background `@sh` agent dies mid-task leaving uncommitted work, independently verify (build/clippy/fmt/tests) and commit the abandoned diff myself rather than discarding and redoing it from scratch, provided it actually holds up under scrutiny.
- Never `taskkill` by image name (`/IM onlyterm-gui.exe`) — always by exact PID captured at launch. This is now a standing, persistent TaskList rule (#408) after an incident earlier in the session where an image-name kill kill two of the user's real, running windows.
