# Alt+V — вставка картинки в Codex: репорт про раскладку (2026-09-11)

Статус: **код не менялся**. Документ фиксирует, что проверено, что исключено, и
гипотезы. Баг достоверно проявился один раз за историю форка, поэтому заранее
ставить логовую инструментацию признано бессмысленным — расчёт на понимание кода.
Смежное августовское расследование: `docs/codex-cyrillic-ctrl-chords.md`.

## Симптом

В панели с Codex CLI вставка изображения в чат по Alt+V:

- при английской раскладке — не сработала;
- после переключения на русскую — сработала;
- после возврата на английскую — продолжала работать.

Направление зависимости противоположно августовскому дефекту (тогда ломалась
русская раскладка, английская работала) — уже одно это говорит, что
воспроизводимый механизм того класса тут ни при чём.

## Фактический контур чорда (проверено по коду, сборка 75fa8bb1 от 2026-09-06)

Каждый этап пути Alt+V от сообщения Windows до байтов в панель сделан
раскладко-независимым серией августовских фиксов, и все они есть в сборке
(проверено `git merge-base --is-ancestor 3e78c9800 75fa8bb1`):

1. `crates/window/src/os/windows/keyboard_layout.rs`,
   `dead_key_probe_modifiers`: plain ALT исключён из dead-key пробы → Alt+V
   не может быть проглочен как «начало dead-key» ни на одной раскладке
   (коммит 3e78c9800).
2. `crates/window/src/os/windows/window.rs`, `key()`: `prefer_physical_for_binding`
   — для CTRL/ALT-чордов код клавиши берётся из физической клавиши
   (`Char('v')` при любой раскладке), а не из ToUnicode.
3. `crates/onlyterm-input-types/src/key_event.rs`,
   `encode_win32_input_mode`: для ALT-чордов `UnicodeChar = 'v'` (0x76)
   всегда, а не `uni=0` (при нуле ConPTY выводил символ сам по активной
   раскладке: под русской получалось «м», и приложение, матчащее по символу,
   чорд не узнавало). Это поле измерено передающимся потомку as-is.
4. Лог живой сессии (`onlyterm-gui.exe-log-9016.txt`): панель Codex
   согласовывает win32-input-mode (DECSET 9001); ветка кодирования выбрана
   верная.
5. codex-rs (`tui/src/keymap.rs`, `MAIN_RESERVED_BINDINGS`): `paste_image` =
   **Ctrl+V и Ctrl+Alt+V**. Чистого Alt+V в Codex нет вообще — это чорд
   Claude Code (он упомянут в комментарии `encode_win32_input_mode`).
6. Пользовательский `~/.onlyterm.ktav`: `{ key: phys:v, mods: CTRL, action:
   PasteFrom: Clipboard }` — **Ctrl+V занят OnlyTerm-овской вставкой текста**
   и потребляется при любой раскладке (phys-биндинги матчатся по физической
   клавише). С картинкой в буфере текстовая вставка даёт пустоту, что внешне
   неотличимо от «не работает».
7. `crates/config/src/config.rs`, `default_ctrl_letter_as_char_processes` =
   `["codex.exe", "codex"]`: нативный Codex получает букву в UnicodeChar для
   CTRL-чордов; с control-кодом Codex чорд молча игнорирует (измерено 16.08,
   коммит 3f1cfb356).

Вывод: на стороне OnlyTerm ни одна ветка текущего кода не может породить
паттерн «EN сломано / RU работает». Старое поведение (`uni=0`, до 3e78c9800)
давало строго противоположный паттерн, и этого кода в сборке уже нет.
Alt+V ничем не перехватывается (дефолты и конфиг проверены).

## Гипотезы (по убыванию правдоподобия)

- **H1 — нажимался Ctrl+V, а не Alt+V.** Его потребляет OnlyTerm (п. 6
  контура) всегда и раскладко-независимо; картинка при этом не вставляется.
  «Заработало» затем могло означать нажатие уже Ctrl+Alt+V (второй чорд
  Codex) или иное отличие жеста. Проверяется по футеру Codex.
- **H2 — разовое состояние самого Codex.** У codex-rs есть матчер чордов с
  таймаутом (`KEY_CHORD_TIMEOUT` в `tui/src/keymap/chords.rs`) и префиксные
  чорды (например ctrl+x): незакрытый префикс заставляет следующую клавишу
  трактоваться как продолжение чорда. Плюс чтение картинки из буфера — само
  по себе операция с состоянием. Зависит от времени, не от раскладки;
  переключение раскладки могло просто совпасть.
- **H3 — транзиент состояния потока GUI (слабая).** В `key()` в ветке
  `prefer_physical` результат `ToUnicode` при `res < 0` игнорируется без
  `clear_key_state()` (в отличие от обычной ветки, где стоит
  `log::error!` + очистка): если раскладка отвечает на Alt+буква
  dead-key-сентинелом (-1) — проба ALT намеренно исключена, поэтому такие
  раскладки не известны, — внутренняя dead-key «диалога» ToUnicode
  остаётся открытой и искажает следующие нажатия. Для en-US/ru-RU таких
  сочетаний не известно; к эпизоду скорее всего не относится, но при будущей
  чистке кода асимметрию стоит иметь в виду.
- **H4 — совпадение по времени.** Между «не сработало» и «сработало»
  неизбежно сменились фокус/клик/состояние TUI; в логе 9016 вокруг
  переключений видны `focus_changed`. Раскладка может быть корреляцией без
  причинности.

## Если воспроизведётся снова

1. Посмотреть, какой чорд показывает футер Codex (Ctrl+V или Ctrl+Alt+V), и
   появляется ли в композере литеральная «v»/«м».
2. Запустить экземпляр с `ONLYTERM_LOG=trace`: трейс уже пишет идентичность
   клавиши и выбранный кодировщик (`diag: key_event_impl key=... mods=...`,
   `diag: chose win32-input-mode path, encoded=...`) — отдельная
   инструментация не нужна.
3. Лог по PID: `~/.local/share/onlyterm/onlyterm-gui.exe-log-<pid>.txt`;
   смены раскладки видны по `diag: active keyboard layout changed`.
