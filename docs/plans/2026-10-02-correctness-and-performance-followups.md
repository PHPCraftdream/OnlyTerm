# Доработки после checkpoint 2026-10-02-1030

## Статус и границы

По последующему запросу пользователя реализация поручена XL в изолированных
worktree; параллельна только статическая работа. Сборки, runtime-проверки,
mutation и performance A/B выполняет основная сессия последовательно.
База исследования: `9bc9bf4d5`, checkpoint `docs/checkpoints/2026-10-02-1030.md`,
дизайн `docs/investigations/2026-10-01-resize-reflow-design.md` и текущие исходники.
На момент первичного исследования `main` совпадал с удалённым `origin/main`; запись checkpoint
про неопубликованные коммиты устарела. Последний альфа-тег — `v0.0.34-alpha`.

Не запускать подагентов, новые окна и синтетическую нагрузку без соответствующей
просьбы пользователя. Не завершать рабочие OnlyTerm-процессы. Для будущих
проверок использовать собственные процессы с зафиксированными PID. При блокировке
бинаря остановиться и сообщить, не освобождать файл завершением чужих процессов.
Бамп версий, коммит, тег и push этим планом не запрашиваются.

## Порядок

1. CF-1 — граничное переполнение reflow.
2. CF-2 — feature-контракт vtparse без default features.
3. CF-3 — поведенческие проверки UTF-8 override escape-parser.
4. PF-1 — измерение реального GUI, resize и задержки ввода.
5. PF-2 и PF-3 — два основных кандидата ускорения; замеры последовательно.
6. PF-4 — изменение гранулярности применения bulk-действий только при подтверждённой задержке.
7. PF-5 и PF-6 — вторичные кандидаты после определения их доли в профиле.

CF-задачи не зависят друг от друга. PF-1 проводится на исправленной базе.
Производительные изменения принимаются только по своему измеренному сценарию;
гипотеза, не давшая прироста, закрывается с отрицательным результатом, без
попадания проигравшего продуктового кода в main.

## Общая приёмка

- Сначала поведенческий reproducer и failing-before/passing-after regression.
  Для производительности — существующий эталон и измерение исходной базы.
- Сохранить текст, атрибуты, границы графем, ширины, wrap-флаги, курсор,
  semantic zones, hyperlinks, stable row indices, историю и поведение ConPTY.
- Использовать существующие differential/native ConPTY проверки; тестирование
  только против своей копии нового алгоритма не является независимым оракулом.
- Cargo запускать без унаследованного `CARGO_TARGET_DIR`, с ограниченным числом
  build jobs; проверки по затронутым пакетам, без одновременных тяжёлых сборок.
- Performance A/B: одна тихая машина, одинаковые входы, прогрев, минимум пять
  чередующихся раундов, медианы и разброс. Для GUI дополнительно p95/p99 latency.
  Не выдавать результат шумного прогона за улучшение.
- Ориентир принятия ускорения: минимум 15% в целевом сценарии; повторяемая
  регрессия более 5% в контрольном сценарии требует исправления или отклонения.
  Если разброс не позволяет различить эффект, результат не подтверждён.
- После smoke: документация/changelog и удаление временной инструментализации.
  Не оставлять глобальный тестовый аллокатор, влияющий на весь пакет.

## CF-1 — переполнение предела ширины reflow (P0)

**Основание:** `onlyterm-surface/src/line/line/editing.rs:137` проверяет
`width + 2 <= u16::MAX as usize`. Для `usize::MAX` и соседних значений складывание
переполняется до выбора обещанного fallback. Замечание пока статическое.

**Работа:** воспроизвести через публичный `wrap_keeping` на реальном C-хранилище;
заменить переполняющееся условие безопасным сравнением с вычтенным пределом.
Не менять алгоритм reflow.

**Приёмка:** нулевая ширина, граница быстрого пути и `usize::MAX - 1`/`usize::MAX`
проходят предусмотренным путём; результат совпадает с reference. Проверить debug
и release, existing surface/term differential regressions, строгий Clippy и fmt.

## CF-2 — восстановление feature-контракта vtparse (P0)

**Основание:** checkpoint сообщает существующий провал
`cargo test -p vtparse --no-default-features`; Cargo.toml задаёт отдельные
`std`, `alloc`, `no_std`, а heapless подключается только через `no_std`.
Падение не перепроверялось ради подтверждения.

**Работа:** согласовать cfg, импорты и зависимости с документированными
поддерживаемыми комбинациями. Не устранять проблему удалением объявленной
возможности или обязательным включением std.

**Приёмка:** исходно падавшая команда и поддерживаемые комбинации features
собираются и проверяют поведение парсера; std-путь остаётся зелёным. Версии
зависимостей не поднимать.

## CF-3 — закрыть пробел UTF-8 override escape-parser (P1)

**Основание:** для `VTActor::print_text_run` в escape-parser checkpoint отмечает
дифференциальное покрытие, но отсутствие mutation-проверок самого override.

**Работа:** проверить consumer-visible поведение, а не форму вызовов:
одиночный/многосимвольный текст, разделение входного UTF-8 на чанки, стыки с
CSI/OSC/C1 и сохранение текста у потребителей `PrintString`, включая
strip-ansi-escapes. Использовать существующие тестовые соглашения.

**Приёмка:** временные мутации потери первого/последнего символа, дублирования
текста и изменения порядка относительно управляющего события ловятся
детерминированными тестами. Эквивалентная группировка Print/PrintString не
считается дефектом, если наблюдаемое поведение одинаково. Мутации удалить.

## PF-1 — профиль GUI и end-to-end latency (P1, прежняя OPT-5)

**Основание:** после ускорения модели не измерена стоимость shaping/paint,
GPU-process/RPC, `ResizePseudoConsole` и ожидания terminal.lock. Reflow модели
не равен полной стоимости перетаскивания окна.

**Работа после разрешения на нагрузку:** собственное окно, обычная диагностика
без trace-шума; фиксированные сценарии ASCII/кириллица/SGR, TUI redraw, несколько
панелей, width/height resize, длинная история. Разделить parse/apply,
lock wait/hold, snapshot, shaping, quad build, IPC, GPU/ack и resize RPC.

**Приёмка:** таблица времени этапов, p50/p95/p99/max задержки ввода и кадра,
аллокации там, где это измеряется изолированно; топ-3 узких места с долей общей
стоимости. Нет вмешательства в рабочие сессии. Сравнение без таймеров
инструментализации подтверждает, что измерение не меняет вывод.

## PF-2 — цветные пустые строки при scroll_up (P1)

**Основание, замерено в checkpoint:** в SGR-per-word 34–47% apply уходило в
создание строк цветной ручкой: 16.8 мс против 0.5 мс с default pen; резко больше
аллокаций. В `screen/scroll.rs` default-строки уже переиспользуются, цветные
проходят `resize_and_clear`/`with_width_and_cell`.

**Работа:** сравнить компактное повторяемое заполнение/переиспользование
Vec-хранилища и шаблон строки с безопасной материализацией при записи.
Не возвращать отклонённое решение «сразу одна кластерная строка»: оно замедлило
последующую печать до x0.79. Выбрать минимальный выигравший вариант.

**Приёмка:** полный цикл «создать -> писать/стирать -> скроллить -> ресайзить»,
не отдельная быстрая конструкция строки. SGR-heavy differential и ConPTY
регрессии зелёные; сохранены backgrounds, wrap, semantic zones и hyperlinks.
Выигрыш в end-to-end apply, отсутствие потери на default-pen и mixed Unicode.

## PF-3 — ускорить не-ASCII reflow (P1)

**Основание:** записанный narrow кириллицы остаётся около 19–22 мс, ASCII —
около 4–5 мс. `ClusteredLine::wrap_pieces_general` проходит grapheme iterator
дважды: определить последний видимый элемент и затем собрать границы кусков.

**Работа:** сначала измерить именно эти проходы. Сравнить сбор границ с
переиспользованием уже вычисленных данных и безопасный ярус одноклеточного
не-ASCII текста. Не вводить вторую несовместимую таблицу ширин и не заменять
графемы Unicode scalar values для произвольного текста.

**Приёмка:** PartialEq с reference, весь reflow differential и native ConPTY
набор. Combining, wide, emoji/ZWJ, zero-width, keep и ширины на границах
сохраняются. Прирост narrow/drag кириллицы подтверждён; ASCII/SGR не ухудшены.
O(history) остаётся честно обозначенным ограничением.

## PF-4 — бюджет работы bulk-действий и отзывчивость (P1, условная реализация)

**Основание, гипотеза:** `LocalPane::with_action_chunks` ограничивает число
Action, но один `PrintString` теперь содержит большой текст. После bulk-путей
тот же лимит числа действий не обязательно ограничивает время под lock.
Фактическая задержка ещё не измерена.

**Работа:** по PF-1 проверить длительность apply/ожидание ввода для крупных
PrintString. Если проблема подтверждена, выбрать ограничение объёмом реальной
работы, не отключая backpressure и не нарушая порядок потока.

**Приёмка:** улучшенный tail latency ввода без регрессии throughput; границы
UTF-8/графем, DEC 2026, capability queries, resize_guard и согласованный
render snapshot сохранены. При отсутствии проблемы закрыть без изменения кода.

## PF-5 — частичный скролл в горизонтальных margins (P2)

**Основание:** `scroll_up_within_margins` собирает cloned клетки во временный Vec,
затем повторно клонирует owned `src_cell` при записи. Это кандидат на уменьшение
копирования; его доля в реальных TUI пока неизвестна.

**Работа:** измерить margin-heavy TUI; убрать лишнее клонирование, при значимой
цене оценить копирование диапазонов без принудительной раскластеризации.

**Приёмка:** клетки вне margins неизменны, partial-scroll не попадает в историю,
атрибуты/wide/гиперссылки сохранены; выигрыш в измеренном сценарии. Не обещать
большой общий прирост от одной механической замены clone на move.

## PF-6 — двойной проход UTF-8 fast path (P2, исследование)

**Основание:** `vtparse::try_print_text_run` вручную проверяет грамматику UTF-8,
затем ещё раз вызывает `core::str::from_utf8`. Это дополнительный проход, но
его доля после OPT-6 неизвестна.

**Работа:** измерить долю и исследовать безопасную организацию сканирования/
валидирования, сохраняющую остановку на C0/C1 и сложность O(input). Нельзя
валидировать весь оставшийся хвост для каждого короткого прогона: получится
повторное сканирование. Не вводить `from_utf8_unchecked` ради бенчмарка.

**Приёмка:** те же parser events/terminal state на валидных, невалидных и
фрагментированных потоках; C1-двойники, truncation, overlong, surrogate и
out-of-range сохранены. Внедрение только при измеренном выигрыше; иначе
документированный отрицательный результат.

## Не включать без отдельного продуктового решения

- Debounce/lazy reflow во время drag: меняет UX и временную модель ConPTY.
- Переписывание Screen на логические строки, полный COW всех ячеек, новый
  renderer: недостаточно измерений для такой стоимости и риска.
- «Оптимизация» снятием защит графем, C1, saved cursor, resize/output ordering
  или сбросом истории/выделения: это изменение поведения, не ускорение.
- Параллельные performance замеры или нагрузка на пользовательские процессы.
